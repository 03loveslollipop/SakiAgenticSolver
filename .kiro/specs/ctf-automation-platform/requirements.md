# Requirements Document: CTF Challenge Automation Platform

## Introduction

This document specifies the requirements for a CTF (Capture The Flag) Challenge Automation Platform that enables users to create and manage Azure VMs that autonomously solve PWN, Crypto, and Reversing challenges using AI agents. The platform provides a web-based dashboard for VM creation, configuration, and real-time interaction with challenge-solving sessions.

## Glossary

- **Platform**: The CTF Challenge Automation Platform system
- **Dashboard**: The web-based user interface for managing VMs and sessions
- **VM**: Virtual Machine running on Azure infrastructure
- **Session**: An active VM instance working on CTF challenges
- **Challenge_File**: A file containing a CTF challenge (binary, encrypted data, etc.)
- **Agent**: An AI agent (Codex or Copilot) that attempts to solve CTF challenges
- **Setup_Script**: A shell script that configures the VM environment with necessary tools
- **Backend**: The Python server component that manages Azure resources and API endpoints
- **Frontend**: The React-based web interface
- **TOOLS.md**: A markdown file documenting all installed tools and their versions on the VM
- **SSH_Key**: Public/private key pair for secure VM access
- **BASE_PROMPT.md**: An immutable system prompt file containing core instructions for the Agent
- **changelog.md**: A file maintained by the Agent documenting all commands and actions performed
- **discoveries.md**: A file maintained by the Agent documenting findings and insights during challenge solving
- **writeup.md**: A final report generated by the Agent summarizing the challenge solution
- **MCP_Server**: Model Context Protocol server providing additional capabilities to the Agent

## Requirements

### Requirement 1: VM Creation and Configuration

**User Story:** As a CTF player, I want to create and configure VMs with specific AI agents and resources, so that I can automate the solving of CTF challenges.

#### Acceptance Criteria

1. WHEN a user submits a VM creation request, THE Platform SHALL create an Azure VM with the specified size configuration
2. WHEN a user selects a small VM size, THE Platform SHALL provision a VM with 2 CPU cores, 2GB RAM, and 30GB disk space
3. WHEN a user selects a medium VM size, THE Platform SHALL provision a VM with 2 CPU cores, 4GB RAM, and 30GB disk space
4. WHEN a user selects a large VM size, THE Platform SHALL provision a VM with 2 CPU cores, 8GB RAM, and 30GB disk space
5. WHEN a user provides challenge file URLs, THE Platform SHALL accept them as a list of one or more URLs
6. WHEN a user selects an AI agent, THE Platform SHALL accept either Codex or Copilot as valid options
7. WHEN a user selects an AI model, THE Platform SHALL accept any model available for the selected agent
8. WHEN a user provides challenge instructions, THE Platform SHALL accept them as text input

### Requirement 2: VM Environment Setup

**User Story:** As a CTF player, I want VMs to be automatically configured with all necessary tools, so that the AI agent can solve challenges without manual setup.

#### Acceptance Criteria

1. WHEN a VM is provisioned, THE Platform SHALL execute the Setup_Script to install required tools
2. THE Setup_Script SHALL install z3 theorem prover on the VM
3. THE Setup_Script SHALL install cryptographic utilities on the VM
4. THE Setup_Script SHALL install decompilers on the VM
5. THE Setup_Script SHALL install debuggers on the VM
6. WHEN the Setup_Script completes, THE Platform SHALL install the selected Agent with the chosen model
7. WHEN the Agent is installed, THE Platform SHALL download all Challenge_Files from the provided URLs
8. WHEN Challenge_Files are downloaded, THE Platform SHALL create an instructions.md file containing the user-provided challenge instructions
9. WHEN instructions.md is created, THE Platform SHALL create a BASE_PROMPT.md file containing immutable system instructions for the Agent
10. WHEN BASE_PROMPT.md is created, THE Platform SHALL create an AGENT.md file containing user-modifiable rules for the Agent
11. WHEN AGENT.md is created, THE Platform SHALL create a TOOLS.md file documenting all installed tools and their versions
12. WHEN all configuration files are created, THE Platform SHALL initialize empty changelog.md and discoveries.md files
13. WHEN all setup is complete, THE Platform SHALL start the Agent with root privileges

### Requirement 3: Dashboard Session Management

**User Story:** As a CTF player, I want to view and manage all my active sessions, so that I can track multiple challenge-solving attempts.

#### Acceptance Criteria

1. WHEN a user accesses the Dashboard, THE Frontend SHALL display a list of all existing Sessions
2. WHEN displaying Sessions, THE Frontend SHALL show the VM size for each Session
3. WHEN displaying Sessions, THE Frontend SHALL show the Agent type and model for each Session
4. WHEN displaying Sessions, THE Frontend SHALL show the creation timestamp for each Session
5. WHEN displaying Sessions, THE Frontend SHALL show the current status for each Session
6. WHEN a user selects a Session, THE Dashboard SHALL navigate to the Session detail view

### Requirement 4: Real-Time Session Interaction

**User Story:** As a CTF player, I want to interact with my VM sessions in real-time, so that I can monitor progress and intervene if needed.

#### Acceptance Criteria

1. WHEN a user views a Session detail, THE Frontend SHALL display a terminal interface connected to that Session's VM
2. WHEN the VM terminal outputs text, THE Frontend SHALL display the output in real-time
3. WHEN a user types in the terminal interface, THE Frontend SHALL send the input to the VM terminal in real-time
4. WHEN a user requests SSH connection details, THE Dashboard SHALL display the SSH hostname and port
5. WHEN a user requests SSH connection details, THE Dashboard SHALL display the SSH username
6. WHEN a user requests to download the SSH key, THE Platform SHALL provide the SSH public key file for download
7. WHEN a user views a Session detail, THE Dashboard SHALL display the current contents of the AGENT.md file
8. WHEN a user edits the AGENT.md file, THE Dashboard SHALL provide a text editor interface
9. WHEN a user saves changes to AGENT.md, THE Backend SHALL update the file on the VM
10. WHEN AGENT.md is updated, THE Platform SHALL notify the running Agent of the configuration change
11. WHEN a user views a Session detail, THE Dashboard SHALL display the current contents of the TOOLS.md file
12. THE Dashboard SHALL display TOOLS.md in read-only mode

### Requirement 5: Backend API and Azure Integration

**User Story:** As a system, I want to manage Azure resources through a Python backend, so that VM operations are reliable and secure.

#### Acceptance Criteria

1. THE Backend SHALL provide a REST API for VM creation requests
2. THE Backend SHALL provide a REST API for listing Sessions
3. THE Backend SHALL provide a REST API for retrieving Session details
4. THE Backend SHALL provide a REST API for terminal interaction
5. THE Backend SHALL provide a REST API for SSH key retrieval
6. THE Backend SHALL provide a REST API for retrieving AGENT.md contents
7. THE Backend SHALL provide a REST API for updating AGENT.md contents
8. THE Backend SHALL provide a REST API for retrieving TOOLS.md contents
9. WHEN the Backend receives a VM creation request, THE Backend SHALL authenticate with Azure using valid credentials
10. WHEN creating a VM, THE Backend SHALL generate a unique SSH_Key pair for that VM
11. WHEN a VM is created, THE Backend SHALL store the Session metadata in MongoDB database
12. WHEN a VM creation fails, THE Backend SHALL return a descriptive error message to the Frontend
13. THE Backend SHALL use MongoDB with Motor (async driver) for database operations
14. THE Backend SHALL connect to MongoDB using connection string with authentication

### Requirement 6: Frontend User Interface

**User Story:** As a CTF player, I want an intuitive web interface, so that I can easily create and manage challenge-solving sessions.

#### Acceptance Criteria

1. THE Frontend SHALL provide a form for creating new VMs with all required configuration options
2. THE Frontend SHALL validate that at least one Challenge_File URL is provided before submission
3. THE Frontend SHALL validate that challenge instructions are provided before submission
4. THE Frontend SHALL validate that an Agent and model are selected before submission
5. THE Frontend SHALL validate that a VM size is selected before submission
6. WHEN a VM creation is in progress, THE Frontend SHALL display a loading indicator
7. WHEN a VM creation succeeds, THE Frontend SHALL navigate to the new Session detail view
8. WHEN a VM creation fails, THE Frontend SHALL display the error message to the user
9. THE Frontend SHALL use React for component-based UI development

### Requirement 7: Security and Access Control

**User Story:** As a system administrator, I want secure VM access and credential management, so that unauthorized users cannot access challenge sessions.

#### Acceptance Criteria

1. WHEN a VM is created, THE Platform SHALL generate a unique SSH_Key pair for that specific VM
2. THE Platform SHALL store SSH private keys securely in the Backend
3. THE Platform SHALL only provide SSH public keys to authenticated users
4. WHEN a user downloads an SSH key, THE Platform SHALL provide the key in standard OpenSSH format
5. THE Backend SHALL validate all API requests before processing Azure operations

### Requirement 8: Agent Execution and Challenge Solving

**User Story:** As a CTF player, I want the AI agent to autonomously attempt to solve challenges, so that I can leverage AI capabilities for CTF competitions.

#### Acceptance Criteria

1. WHEN the Agent starts, THE Platform SHALL execute it with root privileges
2. WHEN the Agent starts, THE Agent SHALL have access to all downloaded Challenge_Files
3. WHEN the Agent starts, THE Agent SHALL have access to the instructions.md file
4. WHEN the Agent starts, THE Agent SHALL have access to the AGENT.md file with general rules
5. THE Agent SHALL have access to all tools installed by the Setup_Script
6. WHEN the Agent produces output, THE Platform SHALL make it available through the terminal interface

### Requirement 11: Agent Documentation and Tracking

**User Story:** As a CTF player, I want the AI agent to maintain detailed documentation of its work, so that I can understand its approach and learn from the solution process.

#### Acceptance Criteria

1. THE Platform SHALL create a BASE_PROMPT.md file that is immutable and not editable by users
2. THE BASE_PROMPT.md file SHALL instruct the Agent to maintain a changelog.md file
3. THE BASE_PROMPT.md file SHALL instruct the Agent to maintain a discoveries.md file
4. THE BASE_PROMPT.md file SHALL instruct the Agent to generate a writeup.md file upon challenge completion
5. THE changelog.md file SHALL contain timestamped entries of all commands and actions performed by the Agent
6. THE discoveries.md file SHALL contain insights, findings, and analysis discovered during the challenge
7. WHEN the Agent completes a challenge, THE Agent SHALL generate a comprehensive writeup.md file
8. THE writeup.md file SHALL include structured metadata with category field (pwn, crypto, reversing, web, forensics, or misc)
9. THE writeup.md file SHALL include structured metadata with technologies field listing relevant tools, techniques, and concepts used
10. WHEN writeup.md is generated, THE Platform SHALL upload it to MongoDB in a writeups collection
11. THE writeup document in MongoDB SHALL include session_id, challenge_urls, completion_timestamp, content, category, and technologies fields
10. THE Platform SHALL provide an API endpoint to retrieve writeups by session_id
11. THE Platform SHALL provide an API endpoint to list all writeups with pagination
12. THE Platform SHALL provide an API endpoint to search writeups by category
13. THE Platform SHALL provide an API endpoint to search writeups by technologies/techniques

### Requirement 12: MCP Server Integration

**User Story:** As a CTF player, I want the AI agent to have access to external knowledge and previous solutions, so that it can leverage past experience and documentation.

#### Acceptance Criteria

1. THE Platform SHALL configure MCP servers for the Agent during VM setup
2. THE Platform SHALL configure a writeup retrieval MCP server that provides access to previous challenge writeups
3. THE writeup retrieval MCP server SHALL allow the Agent to search writeups by keywords or challenge type
4. THE writeup retrieval MCP server SHALL allow the Agent to search writeups by category (pwn, crypto, reversing, web, forensics, misc)
5. THE writeup retrieval MCP server SHALL allow the Agent to search writeups by technologies and techniques used
6. THE writeup retrieval MCP server SHALL return relevant segments from previous writeups
5. THE Platform SHALL configure a documentation MCP server for accessing tool documentation
6. THE Platform SHALL configure a web search MCP server for accessing online resources
7. THE Agent SHALL have access to all configured MCP servers during execution
8. THE MCP server configurations SHALL be documented in the TOOLS.md file

### Requirement 9: Resource Cleanup and Session Termination

**User Story:** As a CTF player, I want to terminate sessions and clean up resources, so that I don't incur unnecessary Azure costs.

#### Acceptance Criteria

1. WHEN a user requests to terminate a Session, THE Backend SHALL stop the VM
2. WHEN a user requests to delete a Session, THE Backend SHALL delete the Azure VM
3. WHEN a Session is deleted, THE Backend SHALL remove the associated SSH_Key pair
4. WHEN a Session is deleted, THE Backend SHALL remove the Session metadata from storage
5. WHEN a VM deletion fails, THE Backend SHALL return a descriptive error message

### Requirement 10: Error Handling and Logging

**User Story:** As a system administrator, I want comprehensive error handling and logging, so that I can troubleshoot issues and monitor system health.

#### Acceptance Criteria

1. WHEN any Azure API operation fails, THE Backend SHALL log the error with timestamp and context
2. WHEN a Setup_Script execution fails, THE Backend SHALL capture the error output and make it available to the user
3. WHEN an Agent installation fails, THE Backend SHALL capture the error and report it to the user
4. WHEN a Challenge_File download fails, THE Backend SHALL report which URL failed and why
5. THE Backend SHALL log all VM creation, modification, and deletion operations
